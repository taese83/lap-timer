## 화면 1 — 랩타임 (측정, 첫 화면)

위→아래: **header(`랩타임` + 우측 `기록 N →` 흰색, 랩 있을 때만)** · 카메라 프리뷰(게이트
스트립) · 상태 배너(IDLE 준비/LEARNING/ARMED/RUNNING) · **대형 타이머**(tabular-nums, hero
스케일) · 타깃 색 칩(인식 모드 등록 후, 탭=새 타깃) · statrow(직전/Best/랩) · **하단 시작
컨트롤**.

**하단 시작 컨트롤 (단일 위젯, 두 제스처)**:
- 넓은 "시작" thumb(좌) + "밀어서 인식 시작 →" 힌트(우측 빈 공간 중앙 정렬, thumb와 비겹침).
- **탭** → 수동 시작(startMode=button): 타이머 즉시 시작.
- **슬라이드 끝까지** → 인식 시작(startMode=detect): LEARNING(~1.5s)→ARMED, 첫 통과에 출발.
- 시작 후 컨트롤 → **[정지]** 버튼(error 색). 정지 = 버튼 탭 **또는** 차 복귀 통과.
- thumb 라운드는 트랙과 동심원(트랙 r-lg 20 − 인셋 4 = 16).

**측정 상태머신**(엔진 계약과 연결): `IDLE → (탭)RUNNING(button) | (슬라이드)LEARNING→ARMED →
(첫 통과)RUNNING(detect) → (복귀 통과 또는 정지)LAP 기록 → IDLE(다음 랩 대기)`. 랩 누적.
인식 모드: 타차 통과 무시(otherPass 카운트), 경계 매칭 랩은 의심 배지. 디바운스 minGap.

## R-camera-reid (2026-08-10) — 30km/h 인식 조사 반영

- **60fps**: 30km/h 통과 창(~20ms) < 30fps 간격(33ms) → 인식이 확률화. `frameRate:{ideal:60}` 요청 +
  실측 fps를 카메라 게이트 캡션에 표시(50 미만 경고색). 60fps 물리 보장 상한 ≈ 35km/h.
- **배치 계약**: 폰 높이 7cm(확정) — 레인 하나가 화면을 채워 가림율 희석 없음. 초점 불요(전역 차분).
- **무채색 시그니처**: signature = hue(24) + 무채색 밝기-대비 4 bin(Δ=luma−배경EMA, ±2T 경계).
  검정/흰/은색 차 재식별 가능. 색 칩은 무채색 peak 시 그레이스케일 스와치.
- **운영 안내**: 동일 무채색 2대는 구분 불가(원리 한계) → 유채색 스티커 권장, suspect 랩 강등 유지.
- NFC 검토 기각: 30km/h 체류(~8ms) < 트랜잭션(10~30ms), iOS Web NFC 부재, 안테나-카메라 위치 충돌.

## R2 (2026-08-10) — 실기기 1차: 감지 전멸 원인 수정

증상(실기기): 첫 인식·정지 후 이후 감지 전멸(N=0), 시작 감지도 간헐 실패.
- **원인 1 — 배경 고착**: 배경이 페이지 로드 첫 프레임에 시드된 후 재시드 없음 + 변화율이
  vibration(15%) 이상이면 배경 학습 영구 차단(주차된 차·노출 출렁임·폰 이동 시 잠금).
- **수정**: ① 카메라를 **밀어서 시작한 감지 세션 동안만** 켠다(세션마다 엔진·배경 신규 —
  구조적 해소, 사용자 확정) ② 엔진 자가복구 2종: 가림 burst > maxBurstMs(2s)면 폐기+배경
  재시드 / 중간 변화율(진동~가림)이 2s 고착돼도 재시드 ③ learning 진입 시 엔진 reset 안전망.
- **실속 완화**: 모션 블러 대비 희석 대응 — 기본 occlusion 40%→30%, pixelDelta 40→28.
- **진단 표면**: 캡션에 실측 fps + 피크 변화율/임계(도달 시 라임) 표시. URL 오버라이드
  `?occlusion=&vibration=&delta=&minGap=&maxBurst=`로 배포 없이 현장 재조정.
- 수동(탭) 모드는 카메라 미사용 — 버튼 정지 전용(사용자 확정으로 기존 "수동+차 인식 정지" 대체).

## R3 (2026-08-10) — 실기기 2차: 매칭 계층이 정지·재시작을 막던 문제

증상: R2 후에도 복귀 정지 안 됨 + 정지 후 재시작 안 됨.
- **원인 — 매칭 과엄격**: ① 타깃 시그니처가 세션을 넘어 영구 보존 → 새 세션(새 카메라·노출)의
  첫 통과가 낡은 타깃과 매칭 실패 → 시작 거부 ② 실속 블러·노출 변화로 같은 차의 통과 간
  L1 거리가 BORDER(1.0) 초과 → 복귀 통과가 "타차"로 무시 → 정지 안 됨.
- **수정**: ① 감지 세션마다 타깃 재등록(startDetect에서 targetSig 초기화) — 세션 간 정체성은
  "내 차를 먼저 출발"이라는 운영 규칙이 담당, 시그니처는 주행 중 타차 무시(1-vs-rest 본연)
  전용 ② SIG_BORDER 1.0→1.5 (동색 블러 변형 흡수, 이색 ≈1.8~2.0은 계속 구분; 경계는 의심 랩)
  ③ ?match=&border= URL 오버라이드로 현장 조정.

## R4 (2026-08-10) — 실기기 3차: 자가 진단 표면 + 카메라 준비 게이트

- **카메라 준비 게이트**: LEARN 타이머를 슬라이드 즉시가 아니라 **스트림 확립(cameraReady) 후**
  시작 — 카메라가 늦게 켜지는 기기에서 스트림 없이 armed가 되고 첫 프레임(배경 시드)이 주행
  중인 차 위에서 찍히던 레이스 제거. learning 중 카메라 미확립이면 배너 "카메라 켜는 중…".
- **진단 표면 3종**: ① 카메라 실패를 침묵하지 않고 캡션에 사유 노출(권한/미지원 등)
  ② 캡션 미터에 누적 프레임 수(f N — 0 고착이면 파이프 사망) ③ 배너에 판정 로그 1줄
  (출발/정지/타차 d=…/디바운스) — 상태머신이 이벤트를 버릴 때 그 사유가 화면에 보인다.

## R5 (2026-08-10) — 실기기 근본 원인 확정: iOS mediaTime 동결

스크린샷 증거: 60fps 표시·프리뷰 정상인데 `f1`·피크 0% 고정 + "출발 — 타깃 등록"은 발생.
→ 프레임은 흐르지만 **rVFC meta.mediaTime이 getUserMedia 스트림에서 전진하지 않음**(iOS).
엔진의 모든 시간 게이트(minGap 300ms·maxBurst 2s·스탯 250ms)가 동결돼 첫 통과만 성공
(-∞ 기준)하고 이후 통과는 영구 디바운스 — "시작은 되는데 정지 안 됨 + N=0"의 근본 원인.
수정: 프레임 타임스탬프 정본을 rVFC/rAF 콜백 시각(now)으로 교체(60fps에서 ±8ms, 오차 예산 내).

## R6 (2026-08-10) — 인식률 향상: 120fps + soft 과도 감지 (+조명 가이드)

- **조명(운영)**: 레인 측면광으로 노출 단축 → 블러·시그니처 열화 감소. 설치 후 손 흔들어
  피크 미터(라임 도달)로 즉석 캘리브레이션.
- **120fps ideal 요청**: 미지원 기기는 자동 하향(무해). 통과 창에 2~4프레임, 보장 상한 70km/h.
  실효 콜백은 디스플레이 주사율에 묶임(ProMotion에서 최대 효과) — 캡션 실측 fps로 확인.
- **soft 과도 감지**: 단일 프레임 30% 외에 "연속 2~5프레임 ≥18% 후 하강"의 짧은 과도도 통과로
  인정 — 실속에서 경계 프레임 2장이 20%대에 걸리던 놓침 회수. 지속 교란(노출 출렁임)은
  기각+억제(조용해져야 재개), soft 선행 에지는 hard burst에 합류해 타이밍 정밀도도 개선.
  오버라이드: ?soft=0.18.

## R7 (2026-08-10) — 카메라 전체 배경 (사용자 제안)

상단 프리뷰 스트립 제거 — 카메라가 켜지면(감지 세션) 화면 전체 배경으로 표시(object-fit
cover + 상하 진한 그라데이션 스크림으로 타이머 가독성 확보, 0.3s 페이드인). 꺼지면 기존
다크 배경. 진단 캡션(fps·피크·f)은 헤더 아래 lens-line으로 이동. 배치 시 레인 정렬을
크게 보며 맞출 수 있는 실용 이점. 캡처 ROI는 비디오 원본 기준이라 엔진 영향 없음.
