# minicar-laptime — 압축 기획 v3 (project-brief)

> 2026-08-05 · v3 확정(사용자 정정 2회 반영): **트랙에 차는 여러 대**, 그중 **카메라에
> 처음 잡히는 차가 자동으로 타깃**이 되고, 그 차가 돌아올 때마다 랩을 잰다.
> 전체 차량 재식별(N대 추적)이 아니라 **단일 타깃 확인(1-vs-rest verification)** —
> "내 차인가 아닌가"의 이진 판별. 제로 셋업(올려두고 켜면 끝)은 그대로 유지.
> 클라이언트 온리 · react-vite-spa · 서버 없음.

## 0. 모드/프로파일

REQUEST_TYPE new-service · AI_MODE **false**(온디바이스 결정론적 CV — 차분+색상
히스토그램, 서버 모델 없음) · LOCAL_DOMAIN_STATE_MODE **true** · WEB_PROFILE

## 1. 제품 정의

- **사용 시나리오**: 여러 대가 함께 도는 트랙. 직선 구간 레인 벽 위에 폰을 다리처럼
  걸쳐 올린다(후면 카메라가 레인 바닥을 내려다봄). [측정 시작] → **처음 지나가는
  미니카가 자동으로 타깃 등록**(색상 시그니처 + t0) → 이후 지나가는 차들 중
  **타깃만 골라** 랩을 기록. 다른 차 통과는 무시.
- **제로 셋업 원칙 유지**: 게이트 긋기 없음, 수동 등록 없음. 유일한 확인 UX는
  첫 통과 직후 "타깃 색 견본 칩" 표시 — 내 차가 아니면 한 번 탭해서 재무장(re-arm).
- **성공 조건(관찰 가능)**: ① 조작 2탭 이내 ② 혼주 중 타깃 랩 누락 0·타차 랩 오기록 0
  (경계 사례는 **의심 배지**로 정직 표시) ③ 오차 ≤ ±1프레임(60fps ±17ms).

## 2. 측정 설계 — 초근접 가림 감지 + 단일 타깃 색상 확인

### 기하가 문제를 절반으로 줄인다
폰이 레인 위 ~5–10cm: 차가 지나가면 화면이 1–3프레임 통째로 가려짐 → **통과 감지**는
전역 차분율 임계로 극도로 견고(v2와 동일). 타미야 트랙은 레인 한 줄이라 차들이
**한 대씩 순차 통과** — 나란히 겹치는 경우가 구조적으로 없음(바짝 붙은 추격만 예외,
§리스크 R2). 남는 문제는 하나: **이 통과가 타깃인가?**

### 타깃 확인 (1-vs-rest) — 색상만이 정본
- 초근접 고속(5–10m/s)에선 모션 블러로 형태·디테일이 뭉개진다 — 그러나 **색 줄무늬가
  돼도 hue 분포는 보존**된다. 특징은 HSV 히스토그램(가림 프레임의 전경 픽셀)뿐.
- **자동 등록**: 첫 통과 burst의 전경 픽셀로 타깃 시그니처 생성. 등록도 블러, 매칭도
  블러 — 대칭이라 오히려 일관적.
- **매칭**: 통과마다 시그니처 거리 계산 → 임계 이하면 타깃(랩 확정), 초과면 타차(무시,
  진단 카운트만). 경계 구간(임계 ±margin)은 랩으로 기록하되 **의심 배지** — 추측으로
  버리지도, 조용히 넣지도 않는다.
- **보조 신호(판정 아님, 배지 강화용)**: 랩 주기 개연성 — 직전 랩 대비 ±60% 이탈이면
  의심 가중. 판정 자체는 색상이 정본(주기로 자동 배정하지 않음 — 값 날조 금지).
- **시그니처 유지**: 확신 매칭에서만 느린 EMA 갱신(조명 드리프트 추종). 경계 매칭에선
  갱신 금지(타차로 오염 방지).

### 파이프라인
```
getUserMedia(후면 60fps, 320×240) → rVFC mediaTime
→ Worker: 전역 차분율 → 가림 burst 검출(임계 40%) → 통과 시각 = burst 시간 중심
→ burst 전경 픽셀 HSV 히스토그램 → 타깃 시그니처와 거리
→ match: 랩 확정(+느린 EMA) / borderline: 랩+의심 배지 / no-match: 타차 무시
→ 디바운스 minGap(기본 0.3s — 타차 통과도 이벤트이므로 v2의 minLapTime과 분리:
   랩 최소 주기는 타깃 매칭에만 적용(기본 2s), 통과 감지 자체는 짧은 간격 허용)
```

### 상태머신
```
IDLE → [시작] → LEARNING(배경 학습 ~1.5s) → ARMED
  → 첫 통과: ENROLLED(시그니처+t0, 색 칩 표시 — 탭하면 ARMED로 재무장)
  → 통과 이벤트: match → LAP(n)+계속 / borderline → LAP(n, suspect) / no-match → 무시
  → [정지] → SESSION_DONE
예외: LEARNING 흔들림 재학습 / 타깃 무통과 60s 배너 / 배경 급변 지속 → 재학습+안내
```

### 정밀도·성능
320×240 전역 차분+히스토그램 = 프레임당 <2ms(Worker). 통과 시각 ±1프레임(60fps
±17ms) — 랩 5–30s 대비 0.06–0.3%. 히스토그램 계산은 burst 프레임(1–3장)에서만.

## 3. MVP 범위

**IN**: 혼주 트랙 단일 타깃(자동 등록+재무장 탭) · 연속 랩 자동 기록 · 타차 무시 ·
의심 배지 · 라이브 보드(현재 랩 경과·직전·best·랩 수·타깃 색 칩) · 세션 IndexedDB
저장 · 결과(랩 리스트·best·avg·σ·의심 표시) · 텍스트 공유 · Wake Lock · 토치 옵션.

**OUT(phase 2)**: N대 전원 동시 계측(전체 재식별 — 부록 §10) · 스플릿 타임 ·
영상 리플레이 · 서버/계정 · tamiya-motor-lab 연동.

## 4. 화면 흐름 (3)

1. **홈** — [측정 시작] / 지난 세션. 첫 방문 거치 안내 1장.
2. **측정** — 미니 프리뷰 + 대형 현재 랩 타이머 + **타깃 색 칩**(첫 통과 후 표시,
   탭=재무장) + 직전/best/랩 수 + 통과 플래시·햅틱(타깃만) + 타차 통과는 미세 틱 표시
   + 상태 배너 + [토치][정지].
3. **결과** — 랩 테이블(best 하이라이트·의심 배지), 타차 통과 수(진단), 공유, 삭제.

## 7. 리스크 대장

| # | 리스크 | 대응 |
|---|---|---|
| **R1** | **유사 색 타차 → false accept**(잘못된 랩) | 보수적 임계 + 경계는 의심 배지 + 주기 개연성 보조 신호. 세션 중 타차 유사도 높으면 "구분 어려움" 배너(스티커 권장) — 조용히 틀리지 않기 |
| **R2** | **바짝 붙은 추격 — burst 병합**(두 차가 한 burst) | burst 길이 sanity(단독 통과 20–40ms vs 병합 60ms+) → 의심 배지. 단일 레인이라 나란히 통과는 구조적으로 없음 |
| R3 | **첫 통과가 내 차가 아님** | 색 칩 확인 UX + 탭 재무장(제로 셋업 유지하면서 정정 1탭) |
| R4 | 트랙 진동 이중 트리거 | 가림(40%) vs 진동(<15%) 임계 이원화 + minGap |
| R5 | 조명 드리프트로 시그니처 이탈 | 확신 매칭만 느린 EMA 갱신 + 저조도 경고 + 토치 |
| R6 | 폰 그림자 저조도 / 점프 차 타격 / 미끄러짐 | 토치 옵션 / 거치 안내(점프 뒤 직선 회피) / 배경 급변 시 재학습 |
| R7 | 저가폰 30fps·iOS 토치 미지원 | ±33ms 강등 표시·기능 게이트 정직 표시 |

## 8. ASSUMPTION

- 첫 통과 차 = 사용자의 차(스펙 정의) — 아니면 재무장 1탭.
- minGap 0.3s(통과 이벤트) / 타깃 랩 최소 주기 2s / 세션 30분 상한.
- 트랙은 단일 레인 순차 통과 기하(타미야 표준). NEEDS_DECISION 없음.

## 9. 검증 계획 씨앗

- 합성 fixture: 타깃 단독 통과 / 타깃+타차 교차 통과(색 상이) / **유사 색 타차**
  (borderline→의심) / 바짝 붙은 병합 burst / 진동 스파이크 / 드랍 프레임 / 조명 드리프트
  → 랩 오기록 0·누락 0·의심 판정 정확성 결정론 검증.
- 실촬영 클립 회귀 2~3개(혼주 포함 1개) — tamiya real-motors 패턴.
- 상태 불변식: 재무장 폐기·suspect 토글·세션 삭제.

## 10. 부록 — N대 전원 동시 계측 (phase 2)

모든 통과를 시그니처 클러스터링해 차별 랩을 동시 산출하는 확장. 자동 등록을 "새
시그니처 발견 시 슬롯 추가"로 일반화하면 UI 없이도 가능하나, 유사 색 쌍의 오배정
리스크가 N²로 커져 별도 검증 라운드 필수. 현 MVP의 시그니처·burst 인프라를 그대로
재사용할 수 있게 엔진 계약을 "통과 이벤트(시각+시그니처) 스트림"으로 설계해 둔다 —
소비층(단일 타깃 필터 vs 클러스터러)만 갈아끼우는 구조.
